# APEX 9 — Compact Research Explanations

## Why
An explicitly requested, local historical research audit used to open a long series of dense facts. The new presentation introduces a short, evidence-first answer suitable for portrait Android: a confirmed historical observation, a significant descriptive difference if any, and the most concrete limitation, all visible before the user expands any detail.

## Source and interpretations
The pure module research-explanation-brief.mjs reads only the already computed Research Synthesis result; it does not acquire candles or infer missing records. It requires DESCRIPTIVE status, matching selected asset and source asset, complete gapless closed H1 archive, a non-empty validated 4H sample, and VERIFIED regime/transition checks. Malformed, absent or incomplete input produces BLOCKED, with no numerical findings.

The leading finding favors actual classified historical regime distribution and attributes its origin. A discrepancy comes only from explicit historical difference findings. No flagged discrepancy is **not** called stable. Limitations prioritize sparse history, missing peers or incomplete holdout; future accuracy has not been established and is explicitly warned about. No confidence score or implied trading advice is introduced.

## Android layout
The compact brief is above the existing provenance strip. Detailed source records are grouped into native, keyboard-and-touch-accessible HTML details panels. Each panel defaults collapsed; its summary shows the number of source items. All original source cards remain visible if opened, and notes do not turn into predictions. No new Android permissions, trading controls, network endpoints, Room migrations, or scheduled jobs.

Cancel, new run and asset-change paths all clear the short brief, status strip and detailed results, avoiding carryover from the previous asset. A blocked source only displays failure and provenance limitations.

## Validation
Tests cover verified source preference, sparse and malformed reports, no unsupported stability claims, descriptive differences, and UI source disclosures. GitHub CI verifies JavaScript and Android APK; narrow-screen, on-device taps and screen reader navigation remain manual validation.
