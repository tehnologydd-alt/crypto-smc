# APEX 9 — уведомления по M1 и сохранение методики исторических M5

## Проверено и исправлено
- Новые H1 (`direction2:`) публикуют `evaluationInterval=1m`, `observationMethod=M1_CLOSED_LEVEL_ORDER_V1`, `stageSemantics=LIMIT_READY_M1_V1`. Старый Android-нотификатор фильтровал только `1m != 5m` и игнорировал новые события.
- Новые M15/H4 (`direction3:`) используют `M1_CLOSED_LIMIT_V1`; ранее опубликованные `M5_CLOSED_LIMIT_V2` сохраняют наблюдение по собственным M5. Старый фильтр `direction2:` игнорировал M15/H4.
- Нотификатор выбирает метод **по неизменяемой гипотезе каждой записи**: M1 только при корректной комбинации модели/интервала/методики; M5 только для соответствующих архивных сценариев. Неподтверждённые старые варианты H1/same-frame не выдаются за M1.
- После законченной M15/H4 синхронизации в WorkManager и по ручному обновлению дополнительно проверяются появившиеся события. ID доставки `forecast.id:stage` и ledger сохраняются прежними: повторная отправка одной стадии исключается.
- Сохранились разрешение пользователя на уведомления, порог включения, ограничение возраста события 6 ч и статус разрешения в Android.
- В сообщении явно показывается реальная доказательная свеча «Закрытая M1» либо «Закрытая M5»; M1 не заменяет и не пересчитывает исторические результаты M5.
- Уведомления остаются фактическими результатами закрытых свечей, **не исполнением ордеров**.
- UI настройки и подсказки обновлены: новые сценарии M1, архивные M5.

## Ограничения
WorkManager Android ограничен системным расписанием: минимальная периодичность около 15 минут, запуск может быть отложен. Наличие M1-анализа не означает доставку push каждую минуту или заранее до события. Информация отображается только после сохранённого подтверждения и разрешения на уведомления. Для проверки доставки на устройстве включить уведомления, синхронизацию и протестировать новые и архивные сценарии.
