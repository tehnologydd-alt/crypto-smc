# APEX 9 — этап 3: проспективное сравнение добавочной информации поставщиков

**Запись правил:** 2026-11-11 (код впервые регистрируется до начала наблюдений).  
**Начало допуска публикаций:** строго позже **2026-11-13 00:00 UTC**.  
**Источник:** полный проверяемый Room-архив избранного актива, максимум 1 500 опубликованных сценариев.  
**Режим:** только чтение, без автономной торговли, дообучения или изменения исходных прогнозов.

## Что измеряем

Раньше APEX считал, был ли источник доступен во время публикации и корректно ли ответил API. Это **не** измеряло полезность источника.

Модуль `source-provider-forward-audit.mjs` проверяет зафиксированную заранее исследовательскую гипотезу:

> При наличии проверенного направления изменения Spot 24ч или видимого дисбаланса стакана фиксированное добавление такого признака к неизменному доисходному баллу помогает различать *завершённые исследовательские исходы* TP3 и STOP лучше, чем один исходный балл, **на точно тех же наблюдениях**.

Это парный анализ изменения ROC AUC (ранжирования). Не вероятность, не прибыль, не причинная оценка, не статистическая значимость и не улучшение реального торгующего ИИ.

### Три предварительно зарегистрированных источника и признаки

| Источник | Действительное опубликованное поле | Знак |
|---|---|---|
| Binance Spot · 24 часа | `market.changePercent24h` | `>0` или `<0`; нулевое изменение не измеряет направление |
| Binance Spot · видимый стакан | `liquidity.visibleDepthImbalance` | `>=+0.10` или `<=-0.10` |
| Bybit Spot · видимый стакан | То же, но **отдельный V2 ID** | Те же фиксированные пороги |

Только `OBSERVED` по действительному поставщику из `sources[kind]`, только при `AS_OF_ROOM_EVIDENCE_V2`; `STALE`, `MISSING`, `NEUTRAL` и неподтверждённый балл не превращаются в отрицательный сигнал. Не допускаются будущие данные.

`NEWS`, `SOCIAL`, `MACRO`, `ONCHAIN` не получают фиктивные корреляции: для них пока сохраняются лишь неподтверждённые метаданные. Без содержания и достоверной связи с активом нельзя измерять их направленный вклад по этой схеме.

## Правила окон и расчёта (зафиксированы до результатов)

- Только M1-верифицированные сценарии M15/H1/H4, по каждому активу и TF **отдельно**, опубликованные после регистрации с Evidence V2. Ни одна M5-запись в сравнение не попадает.
- Для каждого TF по времени публикации выбираются **первые 48 сценариев с непересекающимися исходными горизонтами**. Первый кандидат после окончания прошлого горизонта. Выбор до просмотра outcomes, признаков или источников.
- Три последовательных блока **по 16** публикаций. Для блока 1 разрешены только результаты, записанные **до первой публикации блока 2**; для блока 2 — до первой публикации блока 3. Для блока 3 — до момента текущего аудита. Это препятствует знанию будущих исходов при сравнении ранних периодов.
- Сценарий с непроверенным планом, неизменяемым баллом или evidence не используется для вывода; блок считается `CHECK_DATA`, если запись повреждена. Дубликаты, архив с отсутствующими записями и несоответствия актива отклоняются полностью.
- Исходная база: `0.50*efficiency + 0.30*travelNorm + 0.20*volumeNorm` из **опубликованного до исхода** `preOutcomeStrength`. Для сравнения требуется реальный достоверный объём (`volumeAvailable:true`).
- Фиксированный парный добавочный показатель: `baseline + 0.10*alignment`, `alignment∈{-1,+1}` означает совпадение/несовпадение направления данного источника с направлением опубликованного исследования. **Никакой оптимизации +0.10 по истории.**
- Негативный контроль: `baseline - 0.10*alignment`, сравнивается на тех же строках.
- В каждом периоде нужно **≥12** свежих наблюдений данного поставщика, **≥10** завершённых парных TP3/STOP и **≥3** каждого класса. Недостаток одного из трёх периодов оставляет статус `COLLECTING`.
- Статус `REPEATED_DESCRIPTIVE` только если во всех трёх блоках `ΔAUC≥+0.03`, а контроль с обратным знаком не превосходит базу. Отрицательное недавнее различие (`<=-0.03`) и противоречивые окна отображаются отдельно.
- Порог **описательный, а не тест статистической значимости**: три источника, рыночная зависимость и редкие исходы могут создать ложное впечатление повторяемости.

## Использование и ограничения

- Работа только на текущих избранных активах. Уже существующий автоматический Room-аудит один раз загружает ограниченный архив. **Никаких новых HTTP-запросов для вычисления AUC**.
- Отчёт сохраняется только в виде маленьких счётчиков, ID разрешённых поставщиков и трёх ΔAUC, без цен, адресов, закрытых результатов сделок, токенов API и сырых статей. Новый `SOURCE_COHORT_VIEW_V3` пересчитывается после обновления; старые кэши остаются отдельными.
- UI находится на **существующей** странице источников в сворачиваемом блоке, не создаёт дополнительную вложенную вкладку.
- Не следует интерпретировать `REPEATED_DESCRIPTIVE` как доказательство причинности или разрешение менять алгоритм / совершать сделку.
- Если полный Room-архив превысит предел 1 500 строк, исследование остановится с `INCOMPLETE`, а не станет выдавать ошибочные проценты. Увеличение глубины архива требует отдельного бюджетирования ресурсов и тестов.
- Фоновая работа Android WorkManager остаётся с существующими ограничениями; этот исследовательский модуль ничего не опрашивает сам.
