# APEX — синхронизация Binance / OKX Spot (V1)

Дата: 2026-11-11. Ветка `apex-synchronized-depth-20261111`, продолжает `apex-fresh-market-ws-and-quality-20261111`.

## Проблема

Binance (WS `depth20`, REST `depth100`) и OKX (WS `books5`, REST `books50`) возвращают **разное число уровней** и могут обновляться в разные моменты. Прямое сопоставление процентов дисбаланса из исходных REST/WS-карточек недостоверно: это разные ценовые диапазоны и разные времена. Ни один HTTP/WebSocket ответ не устанавливает личность участников или направление будущей цены.

## Реализовано

1. Открытая вкладка **избранный актив → Данные → Стаканы** показывает два отдельных активных провайдера **Binance** и **OKX**. Bybit полностью скрыт из текущих стаканов и графиков, но исторические записи Bybit в Room и замороженные исследования не удалены.
2. Публичные WebSocket работают при открытой вкладке **Данные** в видимом Android WebView; в случае отсутствия свежих WS-снимков используется лимитированный REST. Для каждого источника сохраняются способ получения, глубина, время и метки ошибок/повторных проверок. REST не отбрасывается из-за более раннего, но уже устаревшего WS. Android-архив не содержит скрытых фальшивых наблюдений.
3. `parseDepthSnapshot` возвращает ограниченный **оперативный** список настоящих по цене упорядоченных уровней `visibleBook` (до 100 на сторону). Он **не** сохраняется в Room и не загружается из истории задним числом. Старые `topVisibleLevels` — лишь восемь самых крупных по объёму уровней, их нельзя использовать для доказательства охвата одинаковой ценовой полосы.
4. `synchronizeSpotDepth` показывает сравнение **только** когда одновременно выполнены все условия:
   - один и тот же Spot-символ (в т.ч. совпадают принадлежность и код актива);
   - обе исходные книги подтверждены стандартным биржевым парсером, получены на телефоне не более **12 секунд** назад;
   - разница между `receivedAt` Binance и OKX — **не более 3000 мс**;
   - подтверждена положительная и упорядоченная книга с минимум двумя реальными заявками с каждой стороны и актуальным ценовым диапазоном на обеих биржах;
   - единая нормализованная полоса цены от `min(10 б.п., реальный наименьший охват с четырёх сторон)`, округлённая **вниз** до 0,1 б.п. и не меньше **0,5 б.п.**. Для каждого провайдера заново считаются суммы видимых Bid/Ask **в одном и том же относительном диапазоне от его mid-price**. Не объединяем неравные полные глубины REST и WS.
5. Если нет данных, не совпадает актив, источник устарел, время расходится или недостаточен одинаковый ценовой диапазон — статус `WAITING / DIFFERENT_ASSET / STALE / MISALIGNED / INSUFFICIENT_COVERAGE / INVALID`. **Общие проценты скрыты, не равны нулю**, карточки отдельных источников продолжают показывать собственные показатели с временем/методом.
6. Это **синхронизация по времени поступления на устройство**. Binance snapshot WS/REST не всегда даёт время, выставленное биржей. Даже когда два ответа получены одновременно, время их исходного формирования могло различаться. UI прямо предупреждает: «Не подтверждает одновременность на биржах».
7. Сравнение является только **описательным**, `predictive=false`, `affectsForecast=false`. Никаких новых уровней, прогнозов, ордеров, обучающих весов, API-ключей, фонового сканирования или лишних постоянных соединений.

Тесты проверяют реальные распарсенные public-ответы, WS + REST, разные валютные пары, подмену актива, задержку более 3 секунд, stale, недостаточную ценовую полосу, невозможность сравнивать только 8 крупных уровней, отсутствие сетевой/торговой логики в синхронизаторе, Android-пакет.

## Android-проверка после установки

1. Установить APK из **этой ветки**; прежняя версия не содержит модуль. Выбрать избранный BTCUSDT или ETHUSDT, открыть **Данные → Стаканы**.
2. Проверить два отдельных источника и статус **«Синхронизировано»** только при близких по времени **реальных** снимках с достаточной глубиной. Для стабильного WS по обеим биржам состояние обновляется вслед за потоками.
3. При отключённом OKX WebSocket может показываться REST; статус синхронизации часто будет `MISALIGNED` или `STALE`. Это корректно: успешный REST не означает одновременный снимок Binance. Отдельные цены/спред остаются видимыми и имеют честные timestamp.
4. При переключении актива до ответа источника прошлый актив не должен попадать в новое сравнение. При сворачивании телефона WebSocket закрывается. Архив сохраняется, но не становится новым живым наблюдением.
5. Сравнить CPU/трафик на физическом устройстве. Нет нового таймера, фонового воркера, внешнего сервера и постоянных записей WS по каждому сообщению.
6. Сверить по независимому журналу API реальную работоспособность OKX в нужной мобильной сети; CI не доказывает доступность WebSocket вне тестового окружения.

**Примечание:** это PR к предшествующей исследовательской ветке, а не объединение в `main`.
