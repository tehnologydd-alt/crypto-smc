# APEX 9 — этап 5: компактная история источников и ресурсная проверка

**Дата:** 2026-11-11  
**Ветка:** `apex-source-ux-resource-stage5`  
**База:** `apex-provider-robustness-stage4`  
**Режим:** только исследование, **без торговли, изменения алгоритма и дополнительных запросов API**.

## Изменения интерфейса

- На существующей странице **Источники** показываются состояния `OBSERVED / STALE / MISSING / LEGACY / INVALID` отдельно для M15, H1 и H4.
- Числа `OBSERVED / STALE / MISSING` — **слоты шести видов evidence в ранее опубликованных проверенных прогнозах**, а не количество успешных HTTP-запросов и не точность прогнозов. Для V4-кэша без новых полей отображается «ожидаем обновления архива», а не выдуманные нули.
- `LEGACY` — публикации, где опубликованный evidence ещё не был сохранён. `INVALID` — структурно непроверенные публикации; это не сбой провайдера.
- Операционная надёжность API остаётся независимой от исследовательской ценности. В существующих раскрываемых блоках остаются ΔAUC, устойчивость и списки поставщиков, без нового уровня навигации.
- Рендер статистики пропускается при неизменных счётчиках, дерево карточек заменяется одним DOM-действием, уже раскрытые блоки сохраняют состояние.
- Колонки на узких Android-экранах становятся одноколоночными, архив распространяется на всю ширину.
- При временной ошибке нативного bridge последняя ранее подтверждённая сводка запросов не исчезает, а помечается как **сохранённая** с отметкой времени.

## Бюджет локального кэша

`source-cohort-summary.mjs` сохраняет компактный `APEX_SOURCE_COHORT_VIEW_V4`. Вносится **аддитивное** поле `feedSummary`, поэтому старый V4-кэш остаётся читаемым.

- Максимум десять активов и **96 000 байт UTF-8** для всего контейнера сводок.
- При переполнении вытесняются **самые старые отчёты**, а новый выбранный отчёт сохраняется, если он сам помещается. Если один отчёт не помещается, исходный кэш остаётся без изменений.
- Экраны могут показать занятую ёмкость этого кэша в КиБ. Это **не** измерение RAM, батареи или интернет-трафика.
- Сырые цены, статьи, ключи, истории ордеров и события TP3/STOP не сохраняются в этом кэше.
- Не добавляется новых задач WorkManager, таймеров API, подписок или дополнительных запросов за историей. Полный Room-аудит по-прежнему последовательный и ограничен 1 500 строками на избранный актив, с ограничением повторов.

## Проверки в CI

```bash
node --test apex9-preview/test-source-stage5-resources.mjs
node --test apex9-preview/test-source-provider-forward-audit.mjs
node --test apex9-preview/test-source-provider-sensitivity.mjs
node --check apex9-preview/free-source-dashboard.mjs
node --check apex9-preview/source-cohort-summary.mjs
node apex9-android/scripts/prepare-web.mjs --check
```

`test-source-stage5-resources.mjs` проверяет пустой архив (без ложных ошибок), десять избранных активов, строгий UTF-8 лимит, вытеснение старейших при переполнении, совместимость старого V4-кэша и отказ хранилища. UI получает только уже сохранённые данные.

Эти тесты **не заменяют** измерения потребления батареи/мобильного интернета и не подтверждают работу Android в реальном фоне после убийства приложения.

## Приёмка Android на физическом устройстве (обязательный smoke-test)

1. **Cold start:** открыть APEX без сети, убедиться, что сохранённые исследования и избранное не исчезают, статус свежести не подделывается; включить сеть и повторить.
2. **До 10 избранных:** проверить, что ни экран, ни фоновые задачи не начинают изучать невыбранные активы; удаление избранного прекращает новые исследования удалённого актива, старые прогнозы остаются доступными согласно политике архива.
3. **Повторный вход на Источники:** не должно происходить новых запросов исключительно ради блока полезности; раскрытые детали не должны произвольно закрываться после записи новой статистики.
4. **Bybit unsupported Spot / HTTP 429 / offline:** ошибка провайдера отображается отдельно от исходов TP3/STOP; кэш не выдаётся за свежее наблюдение.
5. **M1 и возврат из фона:** измерить на реальном устройстве с Android Studio Profiler и журналом API количество сетевых попыток, нагрузку CPU/RAM, расход трафика, длительность полного Room-аудита, Android WorkManager-срабатывания, влияние M1-backfill и потребление батареи за сопоставимый интервал.
6. **Регрессия прогноза:** убедиться, что M5-архив остаётся без изменений, новые M1/V2-прогнозы сохраняют происхождение и ни один статус качества не меняет автоматически веса/ордера.
7. **APK:** сверить SHA256 из GitHub Actions; проверить чистую установку и обновление совместимо подписанной версии. Debug APK с другим сертификатом не является безопасным обновлением приложения.

Без пункта 5 **не заявляем** количественного снижения нагрузки и «проверенного на устройстве» расхода батареи.

## Итоговые ограничения

План этапов 1–5 реализует хранение происхождения, диагностику доступности и описательный forward-only аудит. **Реальные численные выводы о полезности Binance / Bybit пока не готовы:** предварительно установленная дата старта выборки — строго после 2026-11-13 00:00 UTC, нужны 48 непересекающихся M1/V2-публикаций по каждому TF и достаточные завершённые исходы. Новости и социальные метаданные не получают фиктивных оценок точности. Никаких автоматических изменений модели.
