# APEX Whale Intelligence · Этап 3 — Order Blocks на графике + OKX Spot

Дата: 2026-11-11. Ветка: `apex-whale-orderblocks-stage3-okx`, база `apex-whale-intelligence-stage2`.

## График (без торговли)

На существующем **Актив → График** добавлены две независимые отключаемые визуализации:

1. **Order Blocks** — только *структурные гипотезы ценовых зон*, созданные из реальных **закрытых Binance Spot OHLCV** выбранного таймфрейма M1/M15/H1/H4/D1. Для зоны требуется подтверждённый закрытыми свечами BOS/CHoCH и последняя свеча противоположного направления в пределах 12 предшествующих баров **без дыр в истории**. `DEMAND` — от минимума до верхней границы тела исходной медвежьей свечи; `SUPPLY` — от нижней границы тела до максимума исходной бычьей свечи. Зона видна только **после подтверждения пробоя**, максимум 3 одновременно. При закрытии свечи за противоположной границей хранится момент ретроспективной недействительности. Заливка прекращается на последнем реально существующем закрытом баре, а при пропусках баров разрывается. **Это не реально обнаруженные лимитные ордера, не направление сделки, не стратегия и не прогноз.**
2. **W · Крупные переводы** — только события из *ранее проверенного Android Room Whale Stage 1* (BTC/ETH). Метка `W` привязана к **последнему уже закрытому бару на момент первой регистрации транзакции телефоном** (`collectedAt`). Не к будущему свечному закрытию и не к более раннему Blockscout timestamp. Несколько больших выходов одного BTC TX — только один маркер. Неизвестные владельцы, биржи и намерения остаются неизвестными. Не более 16 W-маркеров в видимой области.
3. Обе визуализации **пересчитываются только по уже имеющимся реальным свечам и сохранённым событиям**. Масштабирование/перемещение работает как раньше. Переключатели слоёв не отправляют API-запросы и не меняют сигналы APEX.

## Замена активного стакана Bybit на OKX

С этого этапа **новые публичные Spot-снимки** собираются только с **Binance + OKX** (а не Bybit). Binance продолжает давать подтверждённый источник свечей, как прежде. Для OKX реализован публичный `GET /api/v5/market/books?instId=BTC-USDT&sz=50`:

- символ нормализуется в `BASE-QUOTE`, spot-категория ограничена форматом инструмента;
- `code='0'`, один объект `data[0]`, `asks`, `bids`, `ts`, `seqId`; время OKX проверяется независимо от времени Android (будущее/устаревшее/расхождение часов — отдельные ошибки);
- `51001` — явное отсутствие инструмента; `50011` и HTTP 429 — лимит; HTTP 401/403/451 — доступ ограничен; всё остальное остаётся отдельным `INVALID/OFFLINE`, **без вымышленных котировок**;
- существующий минутный foreground-опрос избранного актива, per-venue cooldown и запись реальных снимков в Room теперь используют **Binance/OKX**. Нет новых фоновых задач, ключей, приватного API, торговли или мониторинга невыбранных активов;
- `getLiquidityHistory` возвращает до 80 последних записей **Binance** и 80 **OKX**. Исходные записи Bybit **не удалены** из Room, оригинальный parser и замороженный provider research V1 остались для аудитируемого архива. Их нельзя переименовать в OKX. Bybit исключён из текущих карточек/графика видимой ликвидности и больше не опрашивается активным исследовательским циклом;
- замороженные сравнительные исследования первого/второго/третьего/четвёртого этапов качества источников, где заранее зарегистрирован Bybit, **не перенастраиваются задним числом**. Новая перспективная оценка полезности OKX потребует отдельной регистрации/отсчёта.

Источники схемы API: официальная документация OKX v5 `GET /api/v5/market/books`, `sz` (уровней на каждую сторону), `ts` (биржевое время), `seqId`. Наличие публичного эндпоинта **не доказывает** стабильную доступность или превосходство OKX на конкретном Android/в регионе: для этого нужны реальные журналы запросов.

## Проверка на Android

1. Установить APK **из этой ветки**, сравнить подпись с установленной версией, открыть избранный BTCUSDT/ETHUSDT, переключать M1, M15, H1, H4, D1. Проверить две кнопки слоёв и pinch/pan.
2. При отсутствии подтверждённого BOS/CHoCH **не должно быть** искусственно нарисованной зоны. При наличии зон убедиться, что начало не ранее подтверждённой свечи, а конец — не в будущем.
3. Буква W появляется только при реально сохранённых source-validated TX и на свечке, закрытой **к моменту первой записи**. На неподдерживаемых монетах W нет.
4. На странице **Актив → Данные** убедиться, что новые состояния бирж **Binance / OKX** реальны и не обновляют Bybit; HTTP 429/451/сбои видны, сохранённый архив не подменяется.
5. Проверить мобильные уведомления/фон, M1 прогнозы, архивные M5, news, экран Радар и историю Room. Сборка GitHub CI не заменяет проверку на физическом устройстве.
6. Для оценки относительной стабильности OKX/Binance собрать фактические счётчики успешных/неуспешных запросов и устаревших снимков за сопоставимые интервалы, без заявления «OKX лучше» по одному успешному ответу.
