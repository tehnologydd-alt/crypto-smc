# APEX · сопоставление Binance / OKX Spot по 50 уровням

## Зачем
WebSocket отображает разные фиксированные уровни: Binance до 20 и OKX до 5 с каждой стороны. Их общие проценты дисбаланса не сопоставимы напрямую. Режим **парных REST-снимков 50/50** запрашивает по 50 ценовых уровней на сторону у обеих бирж, но равная глубина по числу строк не гарантирует одинаковый ценовой охват.

## Когда делается запрос
- Только на странице «Актив → Данные», для активного избранного Spot-символа при видимом приложении с Android Room.
- Оба WebSocket работают и дают валидные данные, но строгая проверка общей полосы возвращает `INSUFFICIENT_COVERAGE`.
- Оба независимых REST-провайдера одновременно допущены существующей политикой лимитов (обычный успешный интервал не меньше 60 секунд, backoff при ошибках / 429).
- Делаются два параллельных публичных GET в одном ограниченном цикле: Binance `/api/v3/depth?symbol=...&limit=50`, OKX `/api/v5/market/books?instId=...&sz=50`.
- Не создаются дополнительные постоянные WebSocket, таймеры или фоновые работники. Нет ключей, аккаунтов или торговых действий.

## Как отображается
- Основные карточки стаканов продолжают показывать последние действительно наблюдённые WS/REST-снимки раздельно, с источником и временем.
- Если основная пара не сопоставима, но обе REST-книги прошли проверки свежести **≤12 с**, локальной разницы времени **≤3 с**, одинакового актива, ценового порядка и общего близкого к mid диапазона, выводится сравнение как **«парный REST 50/50 уровней»**.
- При отсутствии достаточных ценовых уровней или другой ошибке результат остаётся «Сравнение недоступно». Никаких синтетических уровней и переносов архивных снимков.
- Оба процента **для сопоставления** рассчитываются заново только по общей ценовой полосе; они могут отличаться от общих показателей в отдельных карточках.
- Число `50` — верхняя граница запрошенной глубины, а не гарантия фактически доступных 50 уровней. Сравнение показывает только видимую ограниченную ликвидность.
- Время на телефоне означает близкое получение, **не** одновременное состояние площадок.

## Проверки
`node --test apex9-preview/test-depth-synchronization.mjs apex9-preview/test-depth-equal-50.mjs`.

Проверить на Android: вход в избранный актив → Данные, переключение актива/экрана, короткую и редкую видимую ликвидность, REST 429/ошибки сети, отсутствие сравнения после устаревания, расход батареи/сети. Объективная прогнозная точность из сопоставления стаканов **не следует**.
