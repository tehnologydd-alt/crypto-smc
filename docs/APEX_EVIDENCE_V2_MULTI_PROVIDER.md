# APEX 9 — этап 2: multi-provider evidence V2

**Дата:** 2026-11-11  
**Ветка:** `apex-multi-provider-evidence-v2`  
**Основа:** `apex-source-audit-phase1` (отдельный PR #26)

## Цель и архитектура
Новый прогноз должен неизменно фиксировать не только один основной источник `feeds[kind]`, но и **до трёх различных проверенных источников** для каждого типа `kind` (market/liquidity/onchain/news/macro/social). Не восстанавливаем данные задним числом, не делаем дополнительных HTTP-запросов и не меняем алгоритм прогноза.

`ApexEvidenceContext.capture()` использует существующий локальный Room-архив наблюдений, доступный ДО `publishedAt`. `AS_OF_ROOM_EVIDENCE_V2` — это версия JSON-контекста, **не** схема новой таблицы Room.

### Формат
```json
{
  "version": "AS_OF_ROOM_EVIDENCE_V2",
  "capturedAt": 1794400000000,
  "policy": "DESCRIPTIVE_CONTEXT_ONLY_NO_FUTURE_LEAKAGE",
  "feeds": {
    "liquidity": {"state": "OBSERVED", "source": "binance:spot:depth", "...": "old compatible fields"}
  },
  "sources": {
    "liquidity": [
      {"state": "OBSERVED", "source": "binance:spot:depth", "clockBasis": "OBSERVATION_RECORD_TIME", "...": "approved numeric features"},
      {"state": "OBSERVED", "source": "bybit:spot:depth", "clockBasis": "OBSERVATION_RECORD_TIME", "...": "approved numeric features"}
    ]
  },
  "radar": {"...": "unchanged"}
}
```

Схема выше лишь иллюстрация — обязательные поля `observedAt`, `collectedAt`, `ageMs`, `features` для каждого реально записанного источника проверяются кодом. `sources[kind]=[]` означает отсутствие наблюдений этой категории. В результате `feeds[kind]` должен точно соответствовать `sources[kind][0]` без `clockBasis`.

### Гарантии
- **Ассеты:** только текущий избранный актив, без поиска по всем рынкам.
- **Лимит:** максимум 3 уникальных `source` в каждой из 6 категорий, только самый поздний сохранённый снимок каждого поставщика.
- **Время:** `observedAt <= collectedAt <= publishedAt`; свежесть по уже установленным срокам для каждого типа данных. Фактическое биржевое время закрытия известно для `binance:spot:24h`. Остальные наблюдения имеют `OBSERVATION_RECORD_TIME`: эта метка НЕ обещает подтверждённое время поставщика.
- **Данные:** числовые поля проверяются согласно разрешённой схеме; никакие статьи, тексты, кошельки, ключи, URL, персональные данные и оценка «влияния» новости не копируются в evidence.
- **Совместимость:** уже опубликованные `AS_OF_ROOM_EVIDENCE_V1` остаются `VERIFIED` с одним основным `feeds[kind]` и `sources:null`. История M5 не переписывается. Изменение не требует миграции Room.
- **Измерения:** `source-lineage-audit.mjs` считает все фактически замороженные V2-поставщики, отдельно V1, и число публикаций с несколькими поставщиками в одной категории. Это **не** прогнозная точность.
- **Отображение:** существующая панель источников показывает численность V1/V2, многопоставщиковых прогнозов, наблюдённые/устаревшие записи по IDs; без нового экрана и запросов.
- **Ограничение:** новости, социальные сети и макроданные пока являются только непроверенной метаинформацией; отслеживание их наличия не доказывает достоверность содержания.

### Регрессии / условия готовности
- `node --test apex9-preview/test-multi-provider-evidence-v2.mjs`: V1/V2, два стакана, старые данные, несуществующие источники, неверные типы/метки, дубликаты, будущие даты, несовпадение первичного feed и source-array.
- Полный набор CI: `APEX 9 Evidence Core Tests`, `APEX 9 — news and asset research checks`.
- Android: `APEX 9 Research - Android APK`, native Kotlin compile, signed GitHub artifact.
- На физическом Android необходим smoke-тест: сохранение нового V2-поля, перезапуск, фоновые наблюдения избранного, отсутствие потери существующих прогнозов и M1/M5.
